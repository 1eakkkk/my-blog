# 1eak.cool · 个人论坛小站

[进入小站](https://app.1eak.cool) · [更新日志](CHANGELOG.md) · [站内关于页](https://app.1eak.cool/#about)

一个供自己和好友记录生活、分享想法的私人论坛。使用原生 HTML、CSS、JavaScript，运行在 Cloudflare Pages、D1、R2 与 KV 上。

**当前版本**：**v2.8.1**（2026-10-12）。本次整理更新日志、使用说明和页面对齐。**已经运行 v2.8.0 的站点升级到 v2.8.1，无需新数据库迁移，也无需更改绑定。**

## 开始使用

已有账号直接[登录](https://app.1eak.cool/login)。新朋友先向管理员取得邀请码，再在登录页切换到“注册”；一个邀请码可注册一个账号。管理员暂停注册时，已有账号仍可登录。

| 想做什么 | 在哪里操作 |
| --- | --- |
| 写帖子、插入图片或视频 | “发帖”页支持 Markdown 和预览；有序列表按钮会接续已有编号。 |
| 找以前的帖子 | 首页展开“回到某一天”，或在个人主页展开“按日期查找帖子”；有帖日期可点，灰色日期不可选。个人主页可持续加载更早的帖子。 |
| 搜索某句话 | 首页搜索可同时使用分类、日期和排序；结果显示命中附近的正文或评论，评论结果可直接到达对应讨论。 |
| 看别人回复了什么 | “回复我的”显示未读提醒，点击后到达具体评论；评论成功显示后才标记已读。 |
| 找回删除的内容 | “设置 → 内容与备份”打开回收站；先恢复帖子，再恢复主评论和回复。 |
| 保存一份原文 | 帖子详情点击“导出 Markdown”；发帖页及草稿箱也提供导出。导出包含媒体链接，不包含图片或视频文件的副本。 |

首页筛选会保存在链接中，刷新、浏览器前进后退和从详情返回可继续原来的筛选。图片放大只作用于查看器中的图片，关闭后回到原阅读位置；正常网页保留浏览器缩放能力。

### 草稿保存在这台设备上

草稿按账号保存在当前浏览器的 IndexedDB 中，输入后自动保存，刷新可恢复；编辑已发布帖子时保留独立备份。保存区会显示“仅保存在本机”及最后保存时间，失败时提供重试、另存副本和导出。

不同账号的草稿分开存储，同一篇草稿在两个标签页发生版本冲突时会拒绝覆盖。超过十篇不会自动删除旧稿；旧版没有账号归属的草稿只允许确认归属后手动导入，原数据仍保留。

草稿暂不跨设备同步。换浏览器、换电脑或清除网站数据前，先导出需要保留的内容。页面关闭前会尝试补存并提示未保存内容，浏览器无法保证等待异步保存完成。

### 邀请朋友加入

管理员登录后进入“管理 → 邀请朋友，进入小站”，选择有效期并点击“创建邀请码”。界面提供 1、7、30 天，默认 7 天；完整邀请码只显示这一次，复制保存后再交给朋友。

邀请列表可查看使用、过期和撤销状态，并撤销未使用的邀请码。“新账号注册”可切换为“暂停新注册”。站点只保存邀请码的 SHA-256 摘要，之后无法重新查看完整内容；现有账号不受注册开关影响。

帖子、评论、资料和媒体均要求登录。旧 `img.1eak.cool` 图片链接会映射到同源鉴权路径；v2.8.0 上线时已关闭 R2 自定义域名及 r2.dev 公开入口，历史文件仍可在登录后读取。

## 升级与部署

GitHub 的 `main` 分支连接现有 Cloudflare Pages 项目，合并后自动部署。Pages 使用以下绑定：

| 绑定 | 用途 |
| --- | --- |
| `DB` | D1 数据库，包含已有账号、帖子和评论。 |
| `MY_BUCKET` | 私有 R2 桶，保存图片、视频和附件。 |
| `KV` | 登录、上传及写入请求的分组防刷计数。 |
| `TURNSTILE_SECRET` | 服务端验证 Turnstile，并校验本站 hostname。 |

### 从 v2.8.0 升级到 v2.8.1

部署更新后的静态文件和文档即可。没有新增 SQL、账号规则或媒体路径变更，保留既有绑定与数据库。

### 从 v2.7.1 或更早版本升级

1. 先完整备份现有 D1 与 R2，并完成下面的独立恢复验证。
2. 按顺序执行 `migrations/001_registration_invites.sql`、`002_recycle.sql`、`003_reply_inbox.sql`。
3. 部署代码，核对登录、邀请码、帖子、评论、回收站、回复提醒和历史媒体。
4. 确认全部历史媒体可通过 `/api/media/<key>` 登录读取后，关闭 R2 的自定义公开域名与 r2.dev 入口，并检查原直链匿名访问被拒绝。

三份迁移只新增专用表、索引和可见内容视图，可重复执行；保留首次回复提醒启用时间和既有设置。它们用于已有站点升级，**不是空数据库初始化脚本**。现有 D1 还含早期遗留及其它应用表，不能重建、清空或复用它们。

v2.8.0 的正式迁移已执行。只部署媒体代理不能保护仍开放的旧 R2 直链；在其它环境部署时同样需要完成上述公开入口检查。

## 备份与恢复

`tools/backup-site.mjs` 导出完整 D1 SQL，并复制 R2 全部对象的字节、原 key 和元数据；清单记录 SHA-256，下载结束再次核对远端清单。失败目录保留 `INCOMPLETE`，不会被当作完整备份。

在 Node.js 24 和已登录的 Wrangler 环境运行，将占位内容替换为自己的配置。推荐 D1 REST 导出方式：

```sh
node tools/backup-site.mjs --out "<新的绝对备份目录>" --account "<Cloudflare账号ID>" --database "<数据库名称>" --database-id "<D1数据库UUID>" --bucket "<R2桶名>" --oauth-config "<Wrangler config/default.toml路径>"
node tools/verify-backup.mjs "<绝对备份目录>" "<新的绝对恢复验证目录>"
```

也可提供 `CLOUDFLARE_API_TOKEN` 环境变量并省略 `--oauth-config`。OAuth 过期时先通过 Wrangler 刷新登录。使用 Wrangler 导出时，将 `--database-id` 换为 `--config "<配置路径>" --env production --wrangler-js "<bin/wrangler.js路径>"`。

验证工具向新的本地 SQLite 导入 SQL，检查完整性和外键；每个媒体文件独立复制后再核对哈希，并保留 key 与元数据清单。恢复副本会清除旧登录会话，成功后才生成 `VERIFIED.json`。这两条命令不会覆盖生产数据库或删除 R2 对象；备份含私有内容和密码哈希，保存到仓库之外，凭据不会写入备份。

实际灾难恢复时，把验证目录的 `restore.sql` 导入一个**新 D1**，按 manifest 的原 key 与元数据恢复到**新私有 R2 桶**。核对数量、哈希及登录、帖子、评论、媒体后再切换 Pages 绑定；验证完成前保留原库和原桶。

v2.8.0 已完成原库 **44 张表、129 个媒体对象（455,659,596 字节）**的完整备份与独立本地恢复演练；历史媒体鉴权和 258 次原直链匿名访问检查通过。当前没有自动定期备份，也未执行生产灾难切库。D1 Time Travel 可作为额外恢复层，不能代替媒体备份。

## 本地检查

前端无框架，无需安装 npm 依赖。使用 Node.js 24，在项目根目录运行：

```sh
node --check script.js
node --check blog-utils.js
node --check functions/api/posts.js
node --check functions/api/comments.js
node --test tools/*.test.mjs
node tools/check-release.mjs
```

回归测试使用 Node 内置 SQLite 和临时数据库，不连接生产数据；GitHub Actions 的 `Release check` 还检查全部后端 JavaScript 语法。浏览器验证应覆盖窄屏、平板、桌面、明暗主题、键盘焦点和减少动态效果；手机图片手势还需真机检查。仅通过 `file://` 打开页面无法使用 Cloudflare 后端接口。

本站使用 Cookie Session（7 天）、PBKDF2-SHA256 密码哈希及旧密码自动升级。数据库核心表为 `users`、`sessions`、`posts`、`comments`、`likes`、`system_settings`；新版专用表为 `registration_invites`、`content_recycle`、`notification_reads`，展示使用 `active_posts`、`active_comments` 视图，不复用旧 `invites`、`notifications` 表。

主要查询约定：

| 请求 | 用途 |
| --- | --- |
| `/api/posts?archive=1&search=关键词&category=分类` | 首页符合搜索和分类的日期计数，不受当前选中日期限制。 |
| `/api/posts?date=YYYY-MM-DD&page=N&limit=10` | 按日期查看首页帖子，可组合搜索、分类和排序。 |
| `/api/posts?user_id=ID&page=N&limit=20` | 按作者完整分页；加 `archive=1` 查该作者的日期统计。 |
| `/api/comments?post_id=ID&page=N` | 按主讨论分页，每个讨论首批最多 20 条回复。 |
| `/api/comments?post_id=ID&root_id=ID&page=N` | 独立分页读取长讨论的回复。 |
| `/api/comments?post_id=ID&locate_id=ID` | 定位本帖具体评论所在的讨论与回复页。 |

帖子和评论由服务器写入 Unix 毫秒时间戳，显示与日期范围统一使用 UTC+8；相对时间参考 `X-Server-Time`。编辑不改变原发布时间，恢复不改变原 ID、时间、评论与点赞。日期范围包含当天零点、不包含次日零点，历史时间不批量偏移。评论分页依据 `has_more`，定位参数 `root_id` 与 `locate_id` 不能同时使用。

## 维护约定与安全范围

- 输入使用绑定参数，动态表名仅来自代码白名单；需要共同提交的多表写入使用 D1 `db.batch()`，顺序 `await` 本身不是事务。
- 内容 GET/HEAD 同样要求登录和有效账号状态；写入校验 Origin、Fetch Metadata 和内容类型。JSON 请求限 256KiB，上传文件最大 50MiB，检查 MIME、扩展名和实际签名。
- Markdown 使用本地固定 DOMPurify 净化，禁用脚本、内联事件、表单和可执行链接；依赖来源、许可证与 SHA-256 见 `assets/vendor/README.md`，后续持续检查安全公告。
- 媒体由同源接口流式读取并禁止缓存；支持视频 Range、HEAD 和条件请求，PDF 强制下载。MOV、ICO、HEIF 等旧格式仅兼容读取，新上传仍受严格白名单限制。
- KV 对登录、上传及其它写入分别计数，属于尽力防刷，不能作为严格原子限流。现有内联事件使静态 CSP 保留 `unsafe-inline`；文件签名检查不等于病毒扫描。
- 回收站没有自动永久清理。本人可恢复自己删除的内容，管理员删除的内容由管理员恢复；先前单独删除的回复不会随帖子或主评论自动复活。
- 回复提醒排除本人，旧评论首次启用时默认已读；“全部已读”只处理当前快照，新到回复仍未读。回收内容不参与正常列表、搜索、计数和提醒。
