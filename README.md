# 1eak.cool · 个人论坛小站

> [网站地址点击这里](https://app.1eak.cool "1eak的秘密基地")

## 1) 项目总览

基于 Cloudflare 全家桶（Pages + D1 + R2）构建的轻量级私人论坛。采用原生 HTML/JS/CSS 开发，无前端框架，单页应用（SPA）架构。

定位是私人小站，供自己和好友使用，功能以实用为主：发帖、评论、个人主页、媒体上传，后台有完整的管理面板。

**当前版本**：v2.8.0（2026-10-12）。首次升级需按顺序执行 `migrations/001_registration_invites.sql`、`002_recycle.sql`、`003_reply_inbox.sql`；均为新增表、索引或视图，保留原数据和旧版表。

## 2) 技术栈

- **前端**：原生 JavaScript (ES6+)、HTML5、CSS3（CSS Variables、Flexbox/Grid、动画）
- **前端库**：Marked.js（Markdown 渲染）、DOMPurify（XSS 防护）、Cloudflare Turnstile（人机验证）
- **后端**：Cloudflare Pages Functions（Edge 运行时）
- **数据库**：Cloudflare D1（SQLite）
- **对象存储**：Cloudflare R2（图片/视频）
- **缓存/限流**：Cloudflare KV
- **鉴权**：自研 Cookie Session + PBKDF2 密码哈希

## 4) 功能模块

**帖子系统**
- 发帖支持 Markdown（含实时预览）、图片/视频上传
- 有序列表快捷按钮接续已有编号：手动输入 `1.` 后继续生成 `2.`；重复点击追加下一项，选中多行时连续编号
- 图片灯箱支持双指缩放与拖拽，只缩放查看器中的图片；背景页面锁定，关闭后恢复原滚动位置
- 分类：灌水 / 技术 / 生活 / 提问 / 公告
- 心情标签：发帖时可选择心情（😊开心 / 😤吐槽 / 🤔思考 / 😴摸鱼 / 🔥热血 / 😢难过），显示在列表卡片和详情页标题旁
- 阅读时间估算：根据内容字数自动计算，显示在卡片和详情页（中文按300字/分钟）
- 列表视图：最新 / 热度 / 热议三种排序，支持分类筛选、全文搜索和日期筛选
- 首页日期归档：桌面侧栏、手机折叠日历；有帖日期可点击、空日期禁用，可清除日期；日期计数随搜索和分类更新，筛选切换从第一页重新加载
- 列表 / 网格双布局切换，返回列表自动恢复滚动位置

**评论系统**
- 楼中楼：子评论缩进显示，紧跟父评论排列
- 评论分页：每页默认 20 个讨论，每个讨论首批最多 20 条回复，其余通过“加载更多回复”读取；不会将回复丢在主评论之外
- 楼层号：根评论按发布时间和 ID 稳定编号，置顶不改变楼层；置顶回复仍属于原讨论，并让讨论提前展示
- 评论定位：`#post?id=帖子ID&commentId=评论ID` 直接加载目标讨论和回复所在页，可返回全部讨论或从首条回复查看；目标已删除时提示并回到全部讨论
- 加载保护：连续点击不会重复请求，失败可重试；旧帖子请求不会覆盖新帖子的评论
- 回复提示条：点击回复后顶部常驻显示"正在回复 @xxx"
- 字数限制：前后端双重校验，最多 500 字
- 代码块一键复制：hover 代码块时右上角出现复制按钮，复制成功后变绿显示"已复制 ✓"
- 点赞、置顶、编辑、可恢复删除：删除主评论隐藏其回复；恢复时保留原 ID、时间和点赞，先前单独删除的回复仍留在回收站
- 评论同时显示相对时间与 UTC+8 准确时间，相对时间参考服务器时钟

**用户系统**
- 注册：需要管理员生成的单次邀请码，默认 7 天有效，可选 1–30 天；只保存 SHA-256 摘要，可撤销、暂停新注册，现有账号继续登录。用户名仍采用字符白名单
- 登录：失败5次锁定15分钟，旧 SHA-256 密码自动升级为 PBKDF2
- 个人主页：头像、昵称、签名、按作者分页的帖子列表，每页 20 条，点击“加载更多”可访问旧帖
- 日期查帖：展开个人主页的“按日期查找帖子”，深色日期表示当天有帖子，灰色日期不可选；可切换有帖子的月份，点击日期查看当天帖子，点击“显示全部”恢复全部帖子
- 个人主页直接按作者查询服务器，不再从全站最新 50 条帖子中筛选，避免遗漏早期帖子

**站点控制台**（仅管理员）
- 实时统计：在线用户、今日活跃、注册总数、帖子/评论数、有效会话
- 反爬状态：Turnstile 开关、登录失败计数、锁定账号列表
- 内容维护：最近帖子、最近评论、在线用户、公告发布、全站回收站
- 邀请管理：创建后完整邀请码仅显示一次，列表仅显示末六位；分页查看状态和有效期
- 会话维护：清理 7 天前的过期 session

**安全**
- 全局限流：KV 实现，180次/分钟/IP，TTL 自动过期
- XSS 防护：本地固定 DOMPurify 3.4.16；Markdown 按标签/属性白名单净化，禁用表单、脚本、SVG、内联事件与可执行链接
- CSRF 防护：写入请求精确校验 Origin / Fetch Metadata，JSON 接口只接受 JSON，上传接口单独接受 multipart
- 权限：帖子、评论、用户资料读取也要求登录；统一会话过期与封禁限制，回复目标必须属于当前帖子，自动解封不覆盖管理员的新封禁
- 防御头：静态页面 CSP、禁止嵌入、nosniff；API 在 middleware 中独立添加响应头与禁止缓存
- 上传：MIME、扩展名及实际文件签名匹配；头像仅允许站点对象存储的 HTTPS 图片 URL
- 登录：失败次数在数据库中原子累计，保留旧密码升级及既有长密码兼容
- Session 清理：每次用户请求时异步清理 7 天前的过期记录

## 6) 开发规范

- **命名**：JS 变量 camelCase，数据库字段 snake_case
- **SQL**：全部使用参数化查询（`.bind()`），禁止字符串拼接
- **事务**：需共同提交的多表写入使用 D1 `db.batch()`；其中任一语句失败会回滚整个批次，顺序 await 本身不构成事务
- **异步**：不阻塞响应的后台任务使用 `context.waitUntil()`
- **API 返回**：统一格式 `{ success: true, ... }` 或 `{ success: false, error: "..." }`
- **前端交互**：所有异步操作必须有 `showToast` 反馈
- **移动端**：沿用共享响应式断点（1180 / 900 / 600 / 360px），新增组件须检查 320px 小屏、平板、桌面及明暗主题

## 7) 时间与日期规范

帖子和评论由服务器使用 `Date.now()` 写入 Unix 毫秒时间戳（UTC），前端统一按 UTC+8 显示准确时间和划分日期。相对时间参考 API 的 `X-Server-Time`，不对历史数据批量偏移。编辑帖子只更新 `updated_at`，不改变发布时间。

日期归档相关接口：

| 请求 | 用途 |
|---|---|
| `/api/posts?archive=1&search=关键词&category=分类` | 首页所有符合搜索/分类的发帖日期计数，不受当前选中日期限制 |
| `/api/posts?date=YYYY-MM-DD&search=关键词&category=分类&page=N&limit=10` | 首页组合日期、搜索与分类的分页列表 |
| `/api/posts?user_id=ID&page=N&limit=20` | 按作者分页，默认按发布时间和帖子 ID 倒序 |
| `/api/posts?user_id=ID&archive=1` | 返回该作者所有发帖日期及每日帖子数，供日历使用 |
| `/api/posts?user_id=ID&date=YYYY-MM-DD&page=N&limit=20` | 分页返回 UTC+8 指定日期的帖子 |

日期筛选使用当天零点到次日零点的范围，包含开始边界、不包含结束边界。接口校验作者与日期参数，每页最多 100 条。图片缩放的手势限制仅作用于灯箱，正常页面仍保留浏览器缩放能力。

评论接口：`/api/comments?post_id=ID&page=N` 按主评论分页，返回总评论数 `total`、讨论数 `root_total`、`has_more` 及当前讨论和首批回复；主评论附带 `floor`、`reply_total`、`reply_page`、`reply_has_more`。`root_id=ID&page=N` 独立分页读取该讨论的回复；`locate_id=ID` 直接定位本帖评论所在讨论与回复页。加载下一页依据 `has_more`，不再依据 `results.length`。两种定位参数不能同时使用，所有评论查询仍要求登录。

## 9) 安全维护范围

应用代码检查覆盖鉴权与写入权限、评论关联、上传校验、Markdown 渲染、输入边界及响应头。KV 计数属于尽力防刷，不具备严格原子限流；生产流量保护应结合 Cloudflare 的账户配置。当前页面仍使用内联事件，CSP 保留 `unsafe-inline` 以兼容，净化白名单是内容渲染的主要防线。

本站 R2 媒体由同源 `/api/media/<key>` 校验登录和封禁状态后流式读取，禁止缓存，PDF 强制下载；旧 `img.1eak.cool` 链接在渲染时映射到新路径，数据库正文无需改写。部署鉴权代理并验证全部历史文件后，必须关闭 R2 的 custom domain 和 r2.dev 公开入口；单独部署代理不会保护旧直链。历史 MOV/ICO/HEIF 和特殊文件名仅兼容读取，新上传仍按严格类型白名单和签名校验。文件头校验用于拦截类型伪装，不等同病毒扫描。依赖文件、版本、来源、许可证和 SHA-256 在 `assets/vendor/README.md` 中记录；后续需继续检查 DOMPurify 安全公告。本次额外核对了实际 Pages 绑定、R2 公开入口和数据库迁移/备份条件；检查范围及生产验证结果记录在发布验证报告中。

## 10) 草稿、回收站、搜索与回复提醒

- 草稿存储在当前浏览器 IndexedDB 的账号记录中。输入后自动保存，离开发帖页、页面隐藏及关闭前尝试补存；刷新恢复当前草稿，编辑已发布帖子时保存独立备份。保存成功显示 UTC+8 时间，存储失败显示重试、另存副本和导出选项；关闭前仍未保存时提示用户。
- 草稿不会在超过十篇时自动删除；空间不足会明确报错。读写在 IndexedDB 事务中完成，不同页面保存不同草稿不会丢失条目；同篇草稿版本冲突时拒绝覆盖，可加载新版本或另存副本。旧版无账号归属的草稿不自动展示或迁移，确认归属后可手动导入；原数据仍保留。草稿目前仅保存在本机，不同步到服务器。
- 删除帖子/评论只添加回收记录。设置页打开个人回收站，管理员可查看全站；本人只能恢复自己删除的内容，管理员删除的内容由管理员恢复。先恢复帖子，再恢复主评论和回复，没有自动永久清理。帖子详情提供 Markdown 导出，保留正文、时间和媒体链接；它不包含媒体文件的独立副本。
- 搜索按字面处理 `%`、`_`、反斜线，显示命中附近摘录并区分正文/评论；评论结果可直达具体讨论。高亮与摘录均先转义，搜索词不会进入可执行 HTML。
- 首页筛选写入 `#home?search=…&category=…&sort=…&date=…`，刷新、前进后退及详情返回可恢复。有效但没有结果的日期保留空态，不自动取消用户选择。
- “回复我的”包括别人对你的帖子的主评论、别人对你的评论的回复，排除自己的发言。已读回执按账号隔离；目标评论成功显示后标记已读，失败可重试。“全部已读”只处理本次快照，新到的回复仍未读。首次启用之前的评论可在全部列表查看，默认已读；删除/恢复与回收站一致。
- 首次首页保留开场，回访按账号使用紧凑标题，可手动展开；沿用暖纸/暖石墨主题和减少动态效果设置。

## 11) 数据库迁移与完整备份恢复

首次上线前先导出 D1 和 R2 全部媒体并完成独立恢复校验，再按编号执行三个 SQL 文件，最后部署代码。D1 含早期遗留及其它应用表，迁移只新增本站专用结构，不删除或覆盖它们；已验证三个文件可重复执行。Pages 保持现有 `DB`、`MY_BUCKET`、`KV`、`TURNSTILE_SECRET` 绑定。

`tools/backup-site.mjs` 使用 Wrangler 或官方 D1 REST API 导出完整 SQL，并通过管理员 Cloudflare API 读取 R2 的全部对象字节、原 key 和元数据。备份清单保存 SHA-256，复制后再次核对远端清单；失败会保留 `INCOMPLETE`，不会标为完整。管理员凭据只从环境变量或指定的 Wrangler OAuth 配置读取，不写入备份。目录含站点私有数据和密码哈希，应保存到仓库之外。

在 Node.js 24 和已登录的 Wrangler 环境下运行（将占位路径替换为本机实际路径）。推荐直接使用 D1 REST 导出，避开本机原生 CLI 导出故障：

```sh
node tools/backup-site.mjs --out "<新的绝对备份目录>" --account "<Cloudflare账号ID>" --database "<数据库名称>" --database-id "<D1数据库UUID>" --bucket "<R2桶名>" --oauth-config "<Wrangler config/default.toml路径>"
node tools/verify-backup.mjs "<绝对备份目录>" "<新的绝对恢复验证目录>"
```

也可将 `--database-id` 换成 `--config "<配置路径>" --env production --wrangler-js "<bin/wrangler.js路径>"` 使用 Wrangler 导出。可提供 `CLOUDFLARE_API_TOKEN` 环境变量并省略 `--oauth-config`。OAuth 过期时先通过 Wrangler 刷新登录。验证工具向新本地 SQLite 导入完整 SQL，检查完整性与外键，再把每个媒体文件独立复制并二次核对哈希；恢复库清除旧会话，灾难恢复后需重新登录。成功才生成 `VERIFIED.json`。这两条命令不会覆盖线上数据库或删除 R2 对象。

实际灾难恢复时，将验证目录的 `restore.sql` 导入一个新 D1，按 manifest 中的原 key 与元数据将媒体恢复到新的私有 R2 桶，核对数量/哈希和登录/帖子/评论/媒体后再切换 Pages 绑定。保留旧库与旧桶直到验证完成。D1 Time Travel 可作为额外恢复层，不能代替媒体备份；本次完整备份已在独立本地库和媒体目录完成恢复演练。
