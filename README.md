# 1eak.cool · 个人论坛小站

> [网站地址点击这里](https://app.1eak.cool "1eak的秘密基地")

## 1) 项目总览

基于 Cloudflare 全家桶（Pages + D1 + R2）构建的轻量级私人论坛。采用原生 HTML/JS/CSS 开发，无前端框架，单页应用（SPA）架构。

定位是私人小站，供自己和好友使用，功能以实用为主：发帖、评论、个人主页、媒体上传，后台有完整的管理面板。

**当前版本**：v2.7.0（2026-10-11）。此版本无需数据库迁移。

## 2) 技术栈

- **前端**：原生 JavaScript (ES6+)、HTML5、CSS3（CSS Variables、Flexbox/Grid、动画）
- **前端库**：Marked.js（Markdown 渲染）、DOMPurify（XSS 防护）、Cloudflare Turnstile（人机验证）
- **后端**：Cloudflare Pages Functions（Edge 运行时）
- **数据库**：Cloudflare D1（SQLite）
- **对象存储**：Cloudflare R2（图片/视频）
- **缓存/限流**：Cloudflare KV
- **鉴权**：自研 Cookie Session + PBKDF2 密码哈希

## 4) 功能模块

**帖子系统**
- 发帖支持 Markdown（含实时预览）、图片/视频上传
- 有序列表快捷按钮接续已有编号：手动输入 `1.` 后继续生成 `2.`；重复点击追加下一项，选中多行时连续编号
- 图片灯箱支持双指缩放与拖拽，只缩放查看器中的图片；背景页面锁定，关闭后恢复原滚动位置
- 分类：灌水 / 技术 / 生活 / 提问 / 公告
- 心情标签：发帖时可选择心情（😊开心 / 😤吐槽 / 🤔思考 / 😴摸鱼 / 🔥热血 / 😢难过），显示在列表卡片和详情页标题旁
- 阅读时间估算：根据内容字数自动计算，显示在卡片和详情页（中文按300字/分钟）
- 列表视图：最新 / 热度 / 热议三种排序，支持分类筛选、全文搜索和日期筛选
- 首页日期归档：桌面侧栏、手机折叠日历；有帖日期可点击、空日期禁用，可清除日期；日期计数随搜索和分类更新，筛选切换从第一页重新加载
- 列表 / 网格双布局切换，返回列表自动恢复滚动位置

**评论系统**
- 楼中楼：子评论缩进显示，紧跟父评论排列
- 楼层号：根评论显示 #1 #2 #3 编号
- 回复提示条：点击回复后顶部常驻显示"正在回复 @xxx"
- 字数限制：前后端双重校验，最多 500 字
- 代码块一键复制：hover 代码块时右上角出现复制按钮，复制成功后变绿显示"已复制 ✓"
- 点赞、置顶、编辑、删除（删除父评论级联清除子评论）
- 评论同时显示相对时间与 UTC+8 准确时间，相对时间参考服务器时钟

**用户系统**
- 注册：用户名字符白名单（中文/英文/数字/下划线/连字符）
- 登录：失败5次锁定15分钟，旧 SHA-256 密码自动升级为 PBKDF2
- 个人主页：头像、昵称、签名、按作者分页的帖子列表，每页 20 条，点击“加载更多”可访问旧帖
- 日期查帖：展开个人主页的“按日期查找帖子”，深色日期表示当天有帖子，灰色日期不可选；可切换有帖子的月份，点击日期查看当天帖子，点击“显示全部”恢复全部帖子
- 个人主页直接按作者查询服务器，不再从全站最新 50 条帖子中筛选，避免遗漏早期帖子

**站点控制台**（仅管理员）
- 实时统计：在线用户、今日活跃、注册总数、帖子/评论数、有效会话
- 反爬状态：Turnstile 开关、登录失败计数、锁定账号列表
- 内容维护：最近帖子、最近评论、在线用户、公告发布
- 会话维护：清理 7 天前的过期 session

**安全**
- 全局限流：KV 实现，180次/分钟/IP，TTL 自动过期
- XSS 防护：本地固定 DOMPurify 3.4.16；Markdown 按标签/属性白名单净化，禁用表单、脚本、SVG、内联事件与可执行链接
- CSRF 防护：写入请求精确校验 Origin / Fetch Metadata，JSON 接口只接受 JSON，上传接口单独接受 multipart
- 权限：帖子、评论、用户资料读取也要求登录；统一会话过期与封禁限制，回复目标必须属于当前帖子，自动解封不覆盖管理员的新封禁
- 防御头：静态页面 CSP、禁止嵌入、nosniff；API 在 middleware 中独立添加响应头与禁止缓存
- 上传：MIME、扩展名及实际文件签名匹配；头像仅允许站点对象存储的 HTTPS 图片 URL
- 登录：失败次数在数据库中原子累计，保留旧密码升级及既有长密码兼容
- Session 清理：每次用户请求时异步清理 7 天前的过期记录

## 5) 数据库表（D1）

| 表名 | 用途 |
|---|---|
| users | 用户信息、状态、封禁记录 |
| sessions | 登录会话（7天过期自动清理） |
| posts | 帖子内容、分类、置顶状态 |
| comments | 评论、楼中楼关系（parent_id） |
| likes | 点赞记录（帖子/评论） |
| system_settings | 系统开关（如 Turnstile） |

## 6) 开发规范

- **命名**：JS 变量 camelCase，数据库字段 snake_case
- **SQL**：全部使用参数化查询（`.bind()`），禁止字符串拼接
- **事务**：涉及多表写操作使用 `db.batch()` 或顺序 await
- **异步**：不阻塞响应的后台任务使用 `context.waitUntil()`
- **API 返回**：统一格式 `{ success: true, ... }` 或 `{ success: false, error: "..." }`
- **前端交互**：所有异步操作必须有 `showToast` 反馈
- **移动端**：沿用共享响应式断点（1180 / 900 / 600 / 360px），新增组件须检查 320px 小屏、平板、桌面及明暗主题

## 7) 时间与日期规范

帖子和评论由服务器使用 `Date.now()` 写入 Unix 毫秒时间戳（UTC），前端统一按 UTC+8 显示准确时间和划分日期。相对时间参考 API 的 `X-Server-Time`，不对历史数据批量偏移。编辑帖子只更新 `updated_at`，不改变发布时间。

日期归档相关接口：

| 请求 | 用途 |
|---|---|
| `/api/posts?archive=1&search=关键词&category=分类` | 首页所有符合搜索/分类的发帖日期计数，不受当前选中日期限制 |
| `/api/posts?date=YYYY-MM-DD&search=关键词&category=分类&page=N&limit=10` | 首页组合日期、搜索与分类的分页列表 |
| `/api/posts?user_id=ID&page=N&limit=20` | 按作者分页，默认按发布时间和帖子 ID 倒序 |
| `/api/posts?user_id=ID&archive=1` | 返回该作者所有发帖日期及每日帖子数，供日历使用 |
| `/api/posts?user_id=ID&date=YYYY-MM-DD&page=N&limit=20` | 分页返回 UTC+8 指定日期的帖子 |

日期筛选使用当天零点到次日零点的范围，包含开始边界、不包含结束边界。接口校验作者与日期参数，每页最多 100 条。图片缩放的手势限制仅作用于灯箱，正常页面仍保留浏览器缩放能力。

## 8) 本地检查与上线验证

在项目根目录使用 Node.js 24 运行以下命令；无需安装 npm 依赖。功能回归测试使用 Node.js 内置 SQLite 和临时内存数据库，不连接线上数据库。

```sh
node --check script.js
node --check blog-utils.js
node --check functions/api/posts.js
node --check functions/api/comments.js
node --test tools/*.test.mjs
node tools/check-release.mjs
```

GitHub Actions 的 `Release check` 还会检查全部后端 JavaScript 语法。回归测试覆盖有序列表续号、时间格式化、44 篇旧帖的完整作者分页、全站日期归档、搜索/分类组合、UTC+8 午夜边界、快速筛选竞态和无效参数。安全测试使用模拟请求验证私有内容鉴权、CSRF、封禁权限、跨帖回复、输入类型、伪装上传、并发登录锁定、解封竞态、旧长密码及 Turnstile hostname，不攻击生产数据。

上线后建议在真实手机上验证：双指缩放图片时背景页面保持原大小，关闭图片后恢复阅读位置；个人主页可翻到最早帖子，日历筛选与当天帖子一致；评论的准确时间和相对时间一致。浏览器模拟尺寸和合成手势验证不能代替真机手势验证。

## 9) 安全维护范围

应用代码检查覆盖鉴权与写入权限、评论关联、上传校验、Markdown 渲染、输入边界及响应头。KV 计数属于尽力防刷，不具备严格原子限流；生产流量保护应结合 Cloudflare 的账户配置。当前页面仍使用内联事件，CSP 保留 `unsafe-inline` 以兼容，净化白名单是内容渲染的主要防线。

R2 媒体继续使用公开 URL，知道链接即可访问；应用登录墙不会把已有媒体链接变成私有。文件头校验用于拦截类型伪装，不等同病毒扫描。依赖文件、版本、来源、许可证和 SHA-256 在 `assets/vendor/README.md` 中记录；后续需继续检查 DOMPurify 安全公告。此次代码审查不覆盖未提供访问权限的 Cloudflare 账户配置，也不保证消除所有未来漏洞。
